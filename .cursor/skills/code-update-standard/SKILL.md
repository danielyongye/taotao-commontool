# 代码修改规范 Skill

## 适用范围
- **需要调用**：业务逻辑修改、功能迭代、bug 修复、问题定位与排查
- **不需要调用**：纯页面还原（按设计稿搭建 UI 模板/布局/样式，无业务逻辑改动）

## 一、任何代码修改前，必须先出方案
1. 明确需求/问题：
   - 要解决什么问题
   - 影响范围（页面、组件、接口、逻辑）
   - 风险点（是否影响原有功能）
2. 给出至少一种实现方案：
   - 实现思路
   - 修改点清单
   - 预计改动文件
3. 确认方案合理后，再开始写代码。

## 二、代码复用原则（核心）
1. 相同逻辑出现 ≥2 次，必须抽离：
   - 工具函数 → utils/
   - 公共业务逻辑 → composables/ / hooks/
   - 公共UI → components/
   - 接口请求 → api/
2. 禁止复制粘贴代码到处用。
3. 能复用现有组件/方法，绝不重新写。

## 三、代码结构要求
1. 逻辑分层清晰：
   - 视图 < 业务逻辑 < 工具方法 < 接口
2. 函数单一职责：一个函数只做一件事。
3. 避免超大函数、超大文件。

## 四、修改代码时的约束
1. 不随意删原有逻辑，不确定就注释或兼容。
2. 不破坏原有功能，必要时写兼容判断。
3. 变量/方法命名语义化，见名知意。
4. 关键逻辑加简短注释，方便后续维护。

## 五、uni-app + Vue3 特别约束
1. 页面逻辑复杂时，抽离 useXxx.js 复用。
2. 公共样式、公共组件统一维护。
3. 请求逻辑统一封装，禁止到处写 uni.request。

## 六、输出要求
每次帮你修改代码时：
1. 先给出【修改方案】（文字说明）
2. 再给出【具体改动代码】
3. 最后说明【复用抽离了哪些逻辑】
4. 保证无重复代码、可维护、可扩展
